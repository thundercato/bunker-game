## Measurement semantics

`performance.json` is captured from each actually launched simulator app's private
Documents directory. Instrumentation runs only under `--uitesting`, sampling up to
600 callbacks: source resource/setup milliseconds, display-link interval median
and p95, CPU model/render-state update p95, and Mach process resident MB. CPU timing
excludes asynchronous GPU work. Display-link cadence is not a GPU presented-frame
benchmark. RSS is not peak memory, GPU allocation or physical-device footprint.
The small JSON write every 30 callbacks is included in the instrumented run.
No historical baseline speedup is claimed without equivalent old-code telemetry.

Current texture files total approximately 1.1 MB with maximum edge 768 pixels.
This is encoded storage, not decoded GPU memory. Diffuse-only source assets retain
scalar PBR defaults; absent normal/ORM maps are not fabricated. Full PBR parity,
material tint/normal-strength nuances, static geometry merging, true impostor LOD,
terrain painting and physical-device profiling remain future work.

## Renderer decision

Apple machine-readable SceneKit and RealityKit availability was checked again on
8 November. SceneKit remains deprecated from OS 26; RealityKit is available on
TV from 26. This phase establishes useful renderer-independent terrain and world
fixtures, resource sharing and measurements on the existing renderer. It supplies
no comparative RealityKit GPU benchmark. A sensible follow-up is a separate
single-region backend using MeshResource and physically based materials, compared
with the same camera route and budget. Metal would provide the most control but
requires us to own shading/visibility/asset systems; no measured bottleneck yet
justifies that cost. No engine rewrite was performed.
