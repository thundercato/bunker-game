# Field Signal: cloud-first Apple native prototype and Mac handoff

Updated 6 November 2026. This is a **separate experimental workstream**, not a replacement for the current web game or editor. No MacBook is required at the start. Cloud Codex may be Linux-based; do not pretend Xcode runs there.

## Phase A: cloud development now
- Use a new branch and `native/apple/` directory. Read `AGENTS.md`, `docs/CODEX_HANDOFF.md`, `docs/WORLD_DOCUMENT.md`, `docs/DESIGN_DECISIONS_2026-11-06.md` and the latest game/editor PRs. Pin the source revision. Keep canonical web/runtime files read-only.
- Create a reproducible Swift/Xcode project for iPadOS and, if supported by verified Apple SDK/framework requirements, tvOS. Investigate RealityKit/SceneKit/Metal choices against current official Apple docs before settling. The experiment must be **native rendering**, not a WebView or website wrapper. If a tvOS API is unavailable, report it and keep a buildable iPad target rather than faking tvOS support.
- Write portable data and asset conversion tools that validate existing IDs, transforms, dimensions, parent-child relationships and licences. Convert a **small licensed existing Field Signal scene**: outdoor area, a furnished enterable building, door, stairs, search container, torch and simple inventory interaction. Preserve game content provenance and avoid duplicating the whole engine.
- Implement native touch/controller input as appropriate, a TV-readable controller-first UI, and a working vertical slice. Keep native prototype saves separate from real campaigns. The game and editor remain the source of truth for world schema and content.
- Add GitHub Actions **macos-latest** jobs for unsigned simulator builds and tests using available Xcode versions; verify current GitHub-hosted macOS/Xcode availability and SDK requirements. Use `xcodebuild` and appropriate simulator destinations, capture compiler logs and upload build/test artefacts. The Codex cloud task may submit workflows and inspect CI logs even if its own worker is Linux. CI might need permission or have quota/billing limits. Never claim a green build without a completed green run.
- Run platform-independent tests in cloud, then use macOS Actions for actual Apple compilation/simulator tests. No signing certificates, Apple developer credentials, personal secrets or TestFlight upload required at this stage. No unsupported claim of physical-device performance or controller testing.
- Make small commits, push a reviewable PR, record exact successful/failed jobs and checkpoints in `docs/native-apple/PROGRESS.md`, and supply `docs/native-apple/MAC_HANDOFF.md`. Do not merge/publish without approval. Do not wait for a Mac to do useful implementation work.

## Phase B: MacBook Codex later
- Clone/pull the reviewed native branch/PR. Install compatible Xcode and command-line tools; run the documented `xcodebuild` commands and open the project. Resolve any real Mac-specific issues.
- Run iPad and Apple TV simulators where available. Connect physical iPad and supported Apple TV for actual device tests. Validate gamepad recognition, controls, haptics where supported, audio, sustained frame rate, thermals, memory and loading.
- Handle signing, provisioning and TestFlight **only after explicit user approval** and the required Apple developer setup. Never commit signing secrets.
- Compare the same scene and asset budgets with the existing browser game before recommending a full port.
- Keep any Mac changes committed to the same native branch/PR or a clearly linked follow-up. Avoid overwriting concurrent game/editor branches.

## Acceptance and honesty
A cloud task is useful if it delivers source, conversion pipeline, reproducible project, tests and a reviewable PR. A successful GitHub macOS simulator build establishes simulator buildability, not physical iPad/Apple TV compatibility. An Xcode project without a successful compile is **prepared**, not **verified**. Apple TV platform support depends on the chosen native API and deployment target; validate current SDK requirements. The web app remains playable regardless of this prototype.
